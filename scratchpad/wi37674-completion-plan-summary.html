Why that order is not negotiable

agent-tools/loop/arm.ts and loop/checkpoint.ts import resolvePotHomeSlug from pot/wake. Move lib/pot to _retired/ before lifting the substrate out and you break the su engine loop — the replacement system — while lint:no-retired blocks the re-import that would fix it. And deleting the flag before the deciders leave would simply un-retire the tier. Everything else about the sequence is preference; these two are mechanics.

If you want the cheapest wins first

Two items are disproportionately valuable and neither is blocked by anything.

The single genuinely-live reference in the whole audit — the Papercup concierge's delegate path still files-and-nudges a tier that no longer answers. Everything else is either gated, covered downstream, or prose. Fix the code and papercup.converse.md together.

P-065  Five docs that contradict the retirement note

A doc describing a retired tier as live sends the next agent to build against it, and nothing self-corrects that — unlike a wrong “this is retired” claim, which the first grep disproves. Five files, no dependencies, and it stops the bleeding.

P-036  Cold-start autonomy

No system action mints a new su session; an armed loop only re-wakes one that already exists. The Mug was what started work from cold. If every su session ends, nothing restarts the work. Genuine capability loss — needs your call on whether to replace it, and with what.

P-051  The five hive-* routine rows

They are pot-substrate work wearing the old lexicon, not Mug deciders. Default is rename-and-keep, but the hive-canary pot's own status is your call.

depth  Do you want Phase 15 at all?
