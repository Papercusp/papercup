The native installers ship it as today. The container image layers the same bundle onto the runtime rootfs that `papercusp-desktop/scripts/build-rootfs.sh` already produces as an OCI export for WSL (WI-10006429 post 1159706). So the WSL distro and the container image are one artifact (P-061).\\n- **Declared data roots (P-054).** One data-roots module resolves PG data, state, secrets and cache from environment overrides with per-OS defaults. Native installers and the container image set the same variables; the container mounts each root as a volume. Export/import works on roots, so it is variant-independent and cross-variant moves work.\\n- **Export/import (P-055, P-056)** extends `packages/backup` with one consistent producer cut, authenticated full-transfer encryption and durable staged activation. A clean offline destination unlocks the archive with the user-controlled transfer secret; the source DB encryption key is securely wrapped within that envelope and rewrapped/installed only after authentication. Existing HKDF-derived Kopia repository credentials remain an internal backup detail, not the clean-destination unlock prerequisite. All required DB/file/replicated-store producers participate in the recorded cut; incomplete payloads never seal. Import keeps the Phase 0 restore ordering (all data before post-data, user triggers disabled, HNSW memory sizing, staged ANALYZE and required roles), relocates declared paths, preserves readable data keys and creates fresh device identity. Existing durable operation/authority controls implement recovery and handover; destination jobs/schedules/sends remain disabled until verification and explicit activation. Offline source shutdown/fencing is explicit.\\n- **Container defaults from Phase 0 (D-009).** Linux: rootless podman quadlet by default, Docker supported, PG data on a named volume. Windows: run the Server directly in the imported distro on WSL ext4, host networking (podman's 127.0.0.1 forward hangs in mirrored mode, WI-10006715), never /mnt/c. macOS: podman machine on Apple Virtualization.framework, chosen from published data, measured on real Apple silicon at the first Mac E2E (D-007).\\n- **Process supervision (P-059).** The image boots systemd as PID 1 with cgroup delegation, so `managed-spawn.ts` keeps confining agent trees; host-signal readers report `scope: container`.\\n- **GUI connection (P-063).** The thin GUI reuses the BYOC connection manager: a local container Server is one more Server endpoint.\\n- **Proof per requirement.** Tree-plane bars cite unit tests; live-plane bars are verified on real artifacts in the Linux/Windows/macOS test VMs.\\n\\n\\n- **Transfer protocol details (R-20/R-21/R-22).** The transfer envelope records versioned memory-hard KDF parameters (scrypt through maintained Node crypto, with explicit supported parameter/resource bounds), a fresh cryptographic salt and fresh AEAD nonces per export. Secrets and unwrapped data keys are never logged or durably persisted outside their intended encrypted/key-store destination. Authentication completes before any extraction, database execution or destination mutation; wrong-secret, malformed-KDF and tampered input leave destination bytes/database/activation unchanged. Enumerate required producers before capture and use one reusable prepare/quiesce/capture-generation/commit-or-abort/seal protocol. The manifest records each required producer ID and captured generation; missing, failed, timed-out or restarted producers abort the cut and cannot yield a sealed complete export. Resume is idempotent and releases/resumes quiesced writers on abort. Persist transitions restored-isolated -> verified -> handover-committed -> active, bound to transfer/source/destination identity and a monotonic execution-authority epoch. Reuse and extend the current durable-operation and authority/fencing records, rather than create a scheduler or parallel lifecycle service. Online handover commits atomically only after durable source pause acknowledgement; agent claims, schedule dispatch and outward-send execution reject the retired source epoch. Before commit the source may resume only after destination abort; after commit it stays fenced across restart. Rollback after commit requires a reverse authority handover before source re-enable.
