Pointing people at two tabs

Four ways to make Overview and HUD read as the places you go, while the other thirteen stay one click away.

The strip has 15 tabs, and every one carries its own accent colour — indigo, teal, amber, violet, rose, green, lime, blue, pink, emerald, yellow, orange. Colour is currently decoration, not hierarchy: when everything is highlighted, nothing is. That single fact is the cheapest lever available, and three of the four options below pull it.

A · Colour becomes the hierarchy

smallest change

Only Overview and HUD keep their accent. The other thirteen drop to neutral — same position, same order, same click. Nothing moves; the eye just stops being pulled fifteen ways.

A — desaturate secondary
Overview HUD Create Calendar Working Health Frames Git Tests Docs Insights Conversations Learning Evaluation Settings

Gains

  • Zero navigation loss — every tab stays exactly where muscle memory expects
  • Reversible in one commit; it is a styling change, not a structural one
  • Keeps each tab's accent available for its active state, so colour still means something

Costs

  • Weakest guidance of the four — a determined wanderer still sees fifteen doors
  • Thirteen tabs of low-contrast text needs a careful floor, or it fails accessibility

B · Two, a rule, then the rest

recommended

Overview and HUD sit in a raised group, separated by a hairline. Everything after the rule reads as the drawer you go to on purpose. Combines with A — the secondary set is also neutral.

B — primary group + divider
Overview HUD Create Calendar Working Health Frames Git Tests Docs Insights Conversations Learning Evaluation Settings

Gains

  • States the hierarchy structurally, not just tonally — the rule is a claim about importance
  • Still zero clicks lost; nothing is hidden from a new user or from ui:dispatch
  • Dropping the swatches from the secondary set buys back real horizontal room

Costs

  • The strip is still long, and on a narrow window it still scrolls
  • Two visual treatments in one strip needs care not to look like a bug

C · Two tabs and a More menu

strongest guidance

Only the two destinations are on the bar. The other thirteen live behind More, grouped and searchable.

C — overflow menu
Overview HUD More ▾ 13 more

Gains

  • Unambiguous — there are two places to be, and the interface says so
  • Reclaims the entire strip; no horizontal scroll at any width
  • A menu can group and label ("Build", "Inspect", "System") in a way a flat strip cannot

Costs

  • Every secondary tab costs a click and a hunt — worst option for a power user who lives in Git or Tests
  • Hidden means undiscoverable: a new user may never learn Learning or Evaluation exist
  • Most build work, and the least reversible if it turns out to annoy you daily

D · Two tiers

best for wide windows

The two destinations get a real tab bar. The rest becomes a quieter utility row beneath it — present, scannable, clearly subordinate.

Gains

  • Strong hierarchy with no hiding — everything stays one click, always visible
  • The two primaries can afford to be physically larger, which reads as importance faster than colour

  • Spends a row of vertical space on every screen, forever — costly on a dense board like the HUD
  • Thirteen text links can read as a footer rather than navigation if the spacing is off

What I'd ship

B, with A folded into it — primary group, hairline, and a desaturated secondary set. It is the only option that states the hierarchy structurally while costing nobody a click, and it is a styling-and-grouping change to one array in AdvShell.tsx, so it is cheap to try and cheap to undo.

I'd avoid C as a first move. Hiding thirteen tabs is easy to build and hard to walk back — and you are the heaviest user of Git, Tests and Working, so you would feel that click every day. If B proves too weak after living with it, C is the escalation.

Whichever we pick, the tab ids stay as they are. They are serialised into ?tab= URLs, deep links, and the agent ui:dispatch surface — the code comment on harnesses/"Working" already warns that renaming an id breaks all three. This is a presentation change only.

Where the session detail should live

Not "move it all" or "keep it all" — split by how often you look. The bottom strip is in your reading path, so it should carry only what changes while you watch and what you'd act on. The side panel is a lookup surface you consult on purpose.

Keep at the bottomglanceable · changes live
  • Liveness — the dot, and how long since it spoke
  • Context % — is it about to compact mid-thought
  • Current claim — the work item it holds right now
  • Mode chips — AUTO / IDEATE / DRAIN
  • Awaiting — the gate it is parked on

These answer "is this still true?" while you read the transcript. Moving them costs a glance you take constantly.

Move to the panelreference · rarely changes
  • Host, PID, CWD — identity you look up once
  • Resume command — you copy it, you don't watch it
  • Native session ids — debugging detail
  • Locks — a list, not a glance
  • Coord history — a list, not a glance

Long-lived facts and multi-row lists. They make the footer noisy and they never change while you read.

One exception worth keeping in both places: a compact ⚠ 2 locks · 3 unread summary chip stays in the footer and scrolls the panel to that section. The glance stays where you read; the detail moves where there's room.

What else the panel should carry

Ordered by how often it answers the question you actually opened the panel to ask — is this agent healthy, and will it keep going?

01Loop status

Armed? At what interval? When does it next fire? This is the difference between "quiet" and "never waking again" — and nothing in the UI shows it today.

02Current claim

The panel shows PLAN but not the work item. The claim is what the agent is actually doing.

03Context pressure

Used / limit with a bar. The HUD already derives it; the dossier doesn't show it.

04Last checkpoint

The carry note it would resume from. Tells you what a restart actually costs.

05Unanswered directed

How many peers are blocked waiting on this agent to reply.

06Last tool call

Real activity, not heartbeat — a warm-dead session looks alive by heartbeat alone.
