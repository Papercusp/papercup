Left rail · Agents pane

No — most of that tab isn't an LLM.

The pane groups by who owns the code (supervision, health, infra), which is invisible to you. Split it by what actually runs — a model, or a deterministic sweep — and the list stops being a wall.

55

of the 140 non-loop schedules spawn a model. The other 85 are git commits, garbage collection, canary probes and outbox drains — free, deterministic, and only interesting when they break. They're sitting in a tab named "Agents" with equal visual weight.

The evidence

The database already knows which is which

Every routine carries a target_role — the handler it dispatches to. system:blueprint-run, system:scout-cycle, system:overwatch-launch, system:wake-brain and system:loop-wake all spawn a model-backed agent. system:git-sync, system:hive-git-gc, system:telemetry-retention and friends never call one.

Today the pane doesn't use that. It uses AGENT_SPAWNING_PATTERNS — a list of regexes matched against the routine's name. That guess is wrong in both directions, and it is why the current "tokens" flag can't be trusted.

Spawns a model 55 + 770 loop rows · $1,186 / 7d across all roles
Deterministic 85 ≈30 distinct names, fanned out across pots
Rows in one flat list today 877 to find the ~90 that are actually running

Where the fix belongs

Not another regex. registerSystemAction() already takes an options object — add spends: 'llm' | 'none' there, declared by whoever writes the handler and knows the answer, with a test that fails if any registered action leaves it undeclared. The split then becomes a fact the code asserts rather than a pattern it infers.

Naming

What to call the deterministic tab

Pick

System

Reads instantly against "Agents", and it's literally true — every one of these dispatches a system: handler. Zero learning curve, no cleverness to decode.

Machinery

Says "moving parts, no judgment" in one word. Warmer than System, and it pairs nicely with a rail full of kitchen nouns.

Chores

Honest about the register: unglamorous upkeep you only look at when it stops. Slightly undersells the release pipeline.

Clockwork

Deterministic and scheduled in a single word. The most characterful, the least literal — costs a beat to parse the first time.

A · Agents ▸ Loops

The shape

  • Two top-level tabs: Agents (spends money) and System (free). Blender and Docs disappear as tabs — their rows become Learning and Docs lanes here.
  • Inside each tab, one lane per family. System's lanes: Git & release · Cleanup · Health · Federation.
  • Spend lives in the header, quoted per tab — never per row, because usage is recorded by role with no link back to the routine that spawned it.
KeepsThe closest to what's there now — same lane strip, same muscle memory, minimum rebuild.
CostsEight lanes across two tabs. You still have to know which lane a thing lives in before you can find it, which is most of today's problem carried forward.

B · Agents, families inline

The shape

  • Same two tabs, but no lane strip at all. Each tab is one scroll with collapsible family headers carrying their own counts.
  • Your last expand/collapse state persists per family, so the pane settles into whatever you actually watch.
  • The three row kinds get distinct pills: $ spends, flag switch is a feature flag, free deterministic. The padlock retires — it currently means four different things.
KeepsNothing is one click away instead of two — you see every family and its state without navigating. Counts on collapsed headers mean a folded family still reports.
CostsExpand everything and it's a long scroll. Needs the collapse state to be genuinely sticky or it's worse than A.

C · Agents, attention-ordered

The shape

  • No taxonomy at the top level. Every row sorts into Needs you, Spending now, Healthy (one folded line) or Dormant (one folded line).
  • The System tab collapses almost entirely: 31 deterministic routines become the single line "✓ 31 running, last sweep 2m ago" until one fails, at which point it promotes itself into Needs you.
  • Family is still there — as a secondary browse by family view, not the default.
KeepsAnswers the only two questions you actually open this pane with: is anything broken, and what is spending money. 877 rows become about eight.
CostsYou can't browse to a specific routine by memory — finding hive-git-gc means expanding Healthy or searching. Needs a filter box to be livable.

Recommendation

C for the default, B underneath it

C is the honest answer to "simple to understand" — it's the only one where the deterministic half stops consuming attention proportional to its row count. Thirty-one healthy system routines are worth exactly one line until one of them fails, and that's the whole reason a separate System tab is worth building: not to give the plumbing its own room, but to give it a room you never have to enter.

Ship C as the default view with B's family grouping as the second view behind a toggle in the header — the same Working / Runs pattern the /adv Agents panel already uses. That keeps browse-by-family for when you want it without paying for it on every open.

All three share the same foundation, so the read-model work is identical either way: classify by target_role, derive running / stalled / dormant from next_fire_at instead of trusting active, collapse per-pot fan-out into one row per name, and name loops by their owning session rather than a UUID.
