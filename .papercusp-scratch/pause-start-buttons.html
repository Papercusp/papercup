2 · Why it doesn't read — the glyph, at 4×

Same icons, same pixels, magnified. This is the whole complaint in one picture.

The glyphs are outlines. They're lucide <Play> / <Pause> drawn stroke-only — a hollow triangle and two hairline bars. Every transport control anyone has ever used is solid. At 12px a hollow outline reads as a small mark, not a button face. The fix is one prop — fill="currentColor" — same icon set, no hand-rolled SVG.

3 · A second, invisible bug — the glyph isn't centred on your desktop

Both controls set display: inline-flex on the <button> element itself. WebKitGTK — the Tauri webview you actually look at — ignores that and falls back to block layout. Chromium honours it, which is why it looks fine in a browser and wrong in the app.

Chromium — flex honoured
glyph dead-centre
WebKitGTK — flex dropped
glyph sits high and left

This is a known, documented class of bug in this repo — EI-18135716653974462 / WI-5581, and the design lint already flags it as warn-only across ~130 sites. The HUD board hit exactly this and you screenshotted the regression. The fix is the same one that board took: display: block on the button, layout on an inner <span>. Both proposed options above already do it.
