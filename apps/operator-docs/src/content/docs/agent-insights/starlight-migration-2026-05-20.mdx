## What changed in one paragraph

We moved every internal-docs MDX page from `apps/operator/content/internal-docs/` to `apps/operator-docs/src/content/docs/` and rebuilt the surface on Astro 6 + Starlight 0.39 + starlight-llms-txt. The MCP `docs:*` tool surface (outline / get / search) keeps the same JSON shape via a new `starlightContentAdapter` in `packages/docs-engine/`. The docs site itself ships as static HTML in `apps/operator-docs/dist/`, copied into `apps/operator/public/internal/docs/` at build time so Next serves it under the existing URL contract.

## The agent contract still works

- `GET /internal/docs/` — Starlight HTML home.
- `GET /internal/docs/<slug>` — HTML page (Next rewrites to `<slug>.html`).
- `GET /internal/docs/<slug>` with `Accept: text/markdown` — clean markdown twin (`<slug>.md`).
- `GET /internal/docs/llms.txt` — index produced by starlight-llms-txt.
- `GET /internal/docs/llms-full.txt` — full corpus.
- `GET /internal/docs/llms-small.txt` — abridged corpus (new; harmless).

Per-page `Accept: text/markdown` negotiation was originally dropped at the cutover and **restored separately**. `starlight-llms-txt` only emits aggregate `llms*.txt`; we restored the per-page channel by emitting `<slug>.md` twins from `apps/operator-docs/scripts/emit-md-twins.ts` (runs after `astro build`, uses `@papercusp/docs-engine`'s `renderMdxToMarkdown` + `withPreamble`). `proxy.ts` rewrites `Accept: text/markdown` on a bare slug to the static `<slug>.md`. Agents can also use the `docs:get` MCP tool (engine-side, not HTTP) or pull from `/llms-full.txt`.

## Gotchas to know

### 1. `build.format: 'file'` is load-bearing

Starlight default is `format: 'directory'` which emits `dist/<slug>/index.html`. We use `format: 'file'` (set in `astro.config.mjs`) which emits `dist/<slug>.html` instead. Why: Next's static-asset serving from `public/` doesn't honor directory-index trailing-slash semantics globally without setting `trailingSlash: true` site-wide (which would break every other operator route). With `.html` files at the explicit path, we add a single Next rewrite `/internal/docs/:slug+ → /internal/docs/:slug+.html` and the slug-only URL contract works without touching the rest of Next routing.

### 2. The Next rewrite is in `afterFiles`, not the top-level array

`next.config.js` uses the OBJECT form `rewrites() { return { beforeFiles, afterFiles, fallback } }`. The docs rule must go in `afterFiles` so it runs after the Rust opt-in `beforeFiles` rules. If you grep for `return [` looking for the rewrites array, you'll miss it.

### 3. Postbuild copy is in `apps/operator-docs/package.json`

The build script is `"build": "astro build && bash scripts/postbuild-copy.sh"`. If you run `astro build` directly (or just `npx astro build`), the static copy step is skipped and Next will serve stale content. Always run `npm run build` from `apps/operator-docs/`.

### 4. Both fumadocs setups were removed

`apps/operator/source.config.ts`, `apps/operator/lib/source.ts`, `apps/operator/app/(docs)/**`, `apps/operator/app/llms.txt/`, `apps/operator/app/llms-full.txt/`, `apps/operator/app/llms.mdx/`, `apps/operator/app/api/search/` are all gone. Same paths in `apps/papercup/`. If you find references to those, they're stale; remove or update.

### 5. The `fumadocs` plugin slug is unrelated

`@papercupai/fumadocs` (with the `@` prefix) is the name of an internal Papercusp plugin for per-harness docs viewing — NOT the npm package we removed. Plugin manifests, route handlers, and UI code may legitimately reference `fumadocs` as a slug. Don't remove those.

### 6. `<Callout>` → `<Aside>`

47 occurrences across 44 MDX files were rewritten. Type map:
- `<Callout type="info">` → `<Aside type="note">`
- `<Callout type="warn">` → `<Aside type="caution">`
- `<Callout type="warning">` → `<Aside type="caution">`

Import path: `import { Aside } from '@astrojs/starlight/components';`

## Performance

A full `astro build` of the 129-page site completes in ~21s, with
Pagefind search indexing adding ~0.5s. The output is plain static HTML:
the operator serves it straight from `public/internal/docs/`, so there
is **no runtime docs cost** — no second Node process, and no per-request
MDX compilation (fumadocs compiled MDX inside the Next request path).

A head-to-head build-time / bundle-size comparison against the old
fumadocs setup isn't possible — the F10 cutover removed it before a
baseline was captured. The concrete, measurable win is the runtime one
above: docs rendering moved entirely out of the request path.
