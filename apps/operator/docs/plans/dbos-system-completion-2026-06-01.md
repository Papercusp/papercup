**Runtime-foundation prerequisite (D-008 below — added from review):** this audit was *static / prompt-centric*. **Design verdict (JUDGMENT):** DBOS is a genuine improvement, not a lateral move — it pushed deterministic cross-feature *selection* into code and reserved the LLM for the one ambiguous call (per-feature next-step), gaining crash-recovery + failure-isolation the legacy loop lacked. ## Phase 5 — Concurrency safety + the unified dependency model (D-009/D-010/D-011/D-012)

The legacy orchestrator-LLM could *choose* not to co-dispatch two conflicting features; under the deterministic dispatcher that judgment vanished and **nothing replaced it** — concurrent features sharing a file currently race (verified: the chunk-loop `FileLockQueue` is in-process per subprocess, so two feature workers are invisible to each other's locks). Two complementary layers fix this: a **runtime lock floor** that guarantees safety regardless of any agent's judgment (D-010), and a **promote-time parallelism declaration** that lets the promoting agent express intended parallel/serial shape so conflicts are mostly avoided before they reach the floor (D-009).

**The unifying insight (D-012):** a *wave* is just `blocked_by` with uniform edges (every feature in wave N+1 is blocked_by every feature in wave N). Waves, per-feature `blocked_by`, and both flavors of generative expansion all **lower to ONE runtime primitive — a feature graph with `blocked_by` edges, evaluated by a frontier filter on every settle event.** This retires the polled wave-advance sweep, eliminates the lazy-creation provenance race, and unifies P-041/P-042 into the model below. Planning keeps the distinct vocabularies (waves, blockers, generators); promote *lowers* them to edges.

### D-012 — Unify waves + blocked_by + generators into ONE blocked_by graph + a frontier dispatch (DECIDED by avi, 2026-06-01)
Date: 2026-06-01. avi's insight: a wave is just `blocked_by` with uniform edges (wave N+1's features are each blocked_by all of wave N's). So rather than two subsystems (lazy wave-creation + a polled sweep, AND advisory blocked_by), express everything as ONE primitive: a feature graph with `blocked_by` edges, all features created up front at promote, picked by a deterministic **frontier filter**. avi specified the algorithm: at each pick-time compute the WHOLE eligible set in one pass, not per-feature — `terminal = {passed/deprecated}`; `ready = NEEDS_WORK features whose blocked_by ⊆ terminal` (O(V+E), one query + two passes). This is a *frontier* computation (which nodes are ready given the observed terminal set), NOT a topological sort (completion is observed via the status column, not simulated). Topo-sort earns its keep only at PROMOTE time for **cycle detection** (Kahn's) — a dependency cycle is a silent permanent deadlock the runtime filter can't see, so reject it loudly at promote.

Consequences: (a) **the polled wave-advance sweep is RETIRED** (P-044) — a feature settling is exactly the unblock event, and the `setPipelineSettledHook`→`refillHarnessOnSettle` seam already fires event-driven on every settle (no 30s poll; "this polling is disgusting" — avi); (b) the lazy-creation provenance race is sidestepped (all features exist up front; provenance written inline at INSERT, not a separate cross-connection UPDATE — also addresses the wave-agent's reported race bug); (c) **generative `for_each` splits by resolution time** (D-012a): promote-time-resolvable sets expand at promote; *output-dependent* sets ("scan→fix": fix what the scan found) expand at completion-time, riding the settle event.
