The brief

What you asked for

1 “The coord section and others take up huge vertical space if it's a long list, that's bad.”
2 “The difference between what's a label, what's a button, and what's a mode etc, is confusing — make it clearer.”

① and ② are the same disease in two places: nothing in this popup encodes what kind of thing it is. A rail section can't say “I'm long, read the top three”; a chip can't say “I'm a fact, not a button.” Every fix below works by giving each element a form that means something.

The system · answers ②

Five shapes, one meaning each

Before choosing a layout, fix the grammar. Every element in the popup is one of five kinds. Each kind gets a form you can identify without reading the label — shape, border, corner radius, and case all carry the distinction, so it survives a greyscale screenshot and a colour-blind operator.

Specimen sheet the vocabulary all three directions use
KindMeansFormSpecimen
State A fact. Read-only. Changes on its own. Full-round pill, no border, tinted fill, lowercase. live ctx 83%
Mode A state you can change. A switch that is currently on. Pill with a filled cap + caret. Cap on = enabled, grey = off. AUTOon ▾ IDEATEoff ▾
Action Happens the instant you click it. Rectangle, 4px radius, 1px border, icon + Sentence case.
Action → picker Opens a chooser first. Nothing happens yet. Same rectangle, plus a trailing ….
Alert A state that is also a link to its detail. Warn-tinted pill with a trailing ›.
Field Part of a form. Nothing happens until you submit. Recessed well with an inset shadow and a caption above it.
Plan Select plan… ▾
Members 3

Two rules fall out of the table, and they do most of the work.

① Rounded = the system is telling you something. Rectangular = you are telling the system something. Once that holds, you never have to ask whether a thing is clickable-to-change or merely true.

② A trailing … means “a chooser opens”; no ellipsis means “it fires now”. Focus window acts; Grade session… asks first. That one character removes the “I clicked Grade and nothing happened” class of confusion entirely.

  • Pill vs rectangle now separates noun from verb across the whole strip — you can tell state from action without reading a word.
  • AUTO ▾ and Autonomy stop being two objects. The mode pill carries a caret; the button says Set autonomy…. Related, but visibly one badge and one verb.

  • Roughly a day: new vocabulary CSS + reshaping three existing components. No data-layer change.

The chip is the control

What it fixes

  • The GRADE/Grade and AUTO/Autonomy duplicates disappear — there is exactly one object per concept, and it both reports and sets.
  • Every mode is visible, including the off ones. Today a mode that is off renders nothing, so you cannot tell “IDEATE is off” from “this build has no IDEATE”. The grey cap says which.
  • Down to two bands. Status describes the conversation above it; the control band holds everything you can do. ~35px saved on top of A.
  • Resume / Fork / Focus stop shouting. Focus is the common one and stays; the two rarer terminal actions fold into Session….
  • Fleet sits at the far right, visually separated as the only thing that doesn't act on this session.

What it costs

  • Modes move out of the status row, where they read as state today. Some of that reading is real: AUTO genuinely is status. The filled cap is doing the work of carrying that meaning into the control band — worth prototyping on a real agent before committing.
  • A ⋯ Session… menu hides two actions behind a click. Acceptable for fork/resume; would not be for anything used mid-incident.
  • The ChatAction registry currently assumes “one action = one button”. Mode-actions need a second descriptor shape (current value + options) so PostureActions can render as a pill. That is the one real architectural change in this set.
  • Roughly two days, mostly in the registry.

Direction C · the restructure

Everything true goes up. Everything you can do goes down.

Stop solving the confusion with shapes and solve it with position. The header describes the agent; the footer operates it. Nothing read-only appears below the transcript, and nothing clickable appears above it — so “is this a label or a button?” is answered before you look at the control.

What it fixes

  • The rail can never be taller than the rail. One pane is visible, it scrolls inside itself, and the tab strip stays pinned. This is the only option that is structurally immune to ①.

  • Loses the scannable-whole-agent read that R1 and R2's index both keep.

If you want my pick: B + R2.

B because your complaint ② is precisely that a mode and the button that sets it are two indistinguishable objects — and B is the only direction that deletes one of them rather than restyling both. A is safer but leaves the duplicate standing; C is the better layout but keeps the duplicate too, just further apart.

R2 because the rail's real job is triage — “is this agent fine?” — and an index of six headers carrying ok, 2 held, 32 unread, 3 waiting answers that without opening anything. R3 is equally immune to ① and slightly cheaper, but it hides the counts' context; R1 reads best but is the only one that still needs a “where does Open all 32 go?” answer built.

Worth noting: C's header move and B's mode pills are not exclusive. If you like both, the combination is real — state in the header as C draws it, mode pills in the control band as B draws them. That is a fourth direction I'd happily draw up if it's the one you want.

Two things I did not decide for you. First, whether the fleet launcher should leave the popup — WI-6505 put it here deliberately, and overriding that is your call, not mine. Second, the auto-open rule for R2: I've suggested “open anything hot, leave calm sections shut”, but the right default depends on what you actually open when you click an agent.
