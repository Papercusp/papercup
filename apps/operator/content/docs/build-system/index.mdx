## What "the build system" means here

Three different things are bundled by three different commands:

| Artifact | What it is | Built by | Path |
|---|---|---|---|
| **Linux `.deb` / `.rpm`** | Tauri desktop installer for Linux | `npm run build` in `papercusp-desktop/` (runs locally on the dev host) | `papercusp-desktop/src-tauri/target/release/bundle/{deb,rpm}/` |
| **macOS `.dmg`** | Tauri desktop installer for macOS x86_64 | Same `npm run build`, but executed **inside the macOS VM** over SSH | `~/papercupai/papercusp-desktop/src-tauri/target/release/bundle/dmg/` on the Mac VM, then `scp`'d back |
| **Windows `.msi` + NSIS `.exe`** | Tauri desktop installer for Windows | Same, executed **inside the Windows VM** | `C:\Users\User\papercupai\papercusp-desktop\src-tauri\target\release\bundle\{msi,nsis}\` on the Win VM, then `scp`'d back |
| **`:3070` standalone webapp** | Production Next.js standalone of `apps/operator` (the testing surface) | `bin/prod` in the `papercup/` repo | `apps/operator/.next-prod/standalone/` |
| **`:3055` dev server** | The Next.js dev server used by `tauri dev` AND served directly in the browser for fast iteration | `bin/dev` in the `papercup/` repo (papercup-dev systemd user unit) | live, no artifact |

Production Tauri builds are real binaries (~700MB Linux, ~440MB Mac, ~375MB Windows). They contain a bundled Node.js runtime + 5 spawned sidecars (operator-server, embedded-postgres, code-server, zero-cache, mcp-bridge). They do **not** depend on `:3055` at runtime.

## The single entry point: `/admin`

Open `http://localhost:3055/admin` (no nav link — type the URL). Every build / install / VM-launch command in this system is wired into a button there with a live SSE-streamed log.

Three sections:

- **Building** — Linux Prod Build · Mac Prod Build · Windows Prod Build · Rebuild 3070 webapp
- **Running** — Install + launch each platform · Launch Linux Desktop DEV · Restart 3055 · Audit prod bundles · Env probe
- **Simulators** — Launch Android emulator · Start macOS VM · Launch iOS simulator · List iOS sim devices

The button source-of-truth allow-list lives in `apps/operator/lib/admin-commands.ts`. The client only sends a `cmd` id; the server resolves it to the actual shell command — there's no path that lets the client pass raw shell. See [Admin commands](/docs/build-system/admin-commands) for the full reference.
