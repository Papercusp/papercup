# Hyperbee per-table projection pattern

## Context

Phase 5a (papercusp-dogfood-v5 §7.1) wires per-harness Hyperbee state
into the operator's PG mirror. The substrate at
`apps/operator/lib/sync/hyperbee/` provides corestore + Autobase +
projection registry; each consumed table needs its own
`TableProjection<Row>` instance registered at boot.

Eight tables already follow this template:
`contributors`, `feature-claims`, `harness-features`, `feature-queue`,
`prs`, `issues`, `usage`, `presence`. New tables added in later
phases (e.g. `decisions`, `lanes`, `checkpoints`) should mirror it.

## The template

Each projection lives at
`apps/operator/lib/sync/hyperbee/projections/<table>.ts` and exports
two things:

1. A typed row shape + a structural predicate.
2. A `buildXxxProjection(opts: { workspaceId, harnessSlug })` factory
   that returns `TableProjection<Row>` for substrate registration.

```ts
import { getOrgPg } from '@restart/db-org';
import type { TableProjection } from '../projection';

export interface MyRow {
  harness_slug: string;
  // ...other PG columns
}

export interface MyProjectionOpts {
  workspaceId: string;
  harnessSlug: string;
}

function composeKey(row: MyRow): string {
  // Match hyperbee-key-types.ts. Per-harness Hyperbee, so the
  // "harness/" prefix is implicit — return only the unique suffix.
  return row.feature_id;                       // or `${a}/${b}` for composite
}

export function isMyRow(input: unknown): input is MyRow { /* strict */ }
function decodeValue(raw: unknown): MyRow | null {
  return isMyRow(raw) ? raw : null;
}

async function writeToPg(opts: MyProjectionOpts, row: MyRow): Promise<void> {
  if (row.harness_slug !== opts.harnessSlug) return;   // cross-harness drop
  const { sql } = getOrgPg();
  await sql`
    INSERT INTO harness_shared.my_table (...) VALUES (...)
    ON CONFLICT (...) DO UPDATE SET ...
  `;
}

async function deleteFromPg(opts: MyProjectionOpts, key: string): Promise<void> {
  // Parse composeKey() inverse. Gracefully no-op on malformed input.
}

export function buildMyProjection(opts: MyProjectionOpts): TableProjection<MyRow> {
  return {
    tableTag: 'my-table',                      // matches HYPERBEE_TABLE_TAGS
    composeKey,
    decodeValue,
    writeToPg: (row) => writeToPg(opts, row),
    deleteFromPg: (key) => deleteFromPg(opts, key),
  };
}
```

## Five rules from shipping the first eight

1. **`composeKey` returns only the suffix.** The substrate prefixes
   with the tag from `hyperbee-key-types.HYPERBEE_TAG_TO_PREFIX`.
   Don't include `tableName/` yourself.

2. **`decodeValue` must drop malformed remote ops silently** — return
   `null`, never throw. A bad op from a peer must not crash the
   projection loop. Cover every field with a type predicate (string
   length, integer-ness, finite number, null-or-string union, etc).
   The eight existing projections each have 10-14 tests exercising
   the rejection paths.

3. **Cross-harness writes get dropped.** Projections are registered
   per-harness. If a remote op for harness X reaches harness Y's
   projection (shouldn't happen, but defensive), `writeToPg` returns
   early instead of writing the wrong PG row.

4. **Append-only tables refuse `del`.** `feature-claims` and `usage`
   use `ON CONFLICT DO NOTHING` for writes and a silent-no-op
   `deleteFromPg`. The contract is in the schema, not enforceable
   at the substrate level.

5. **Epoch-ms timestamps convert via `to_timestamp(x / 1000.0)`.**
   PG stores `TIMESTAMPTZ`; Hyperbee stores `number`. The
   `${ts == null ? null : sql\`to_timestamp(${ts} / 1000.0)\`}`
   pattern handles nullable cases.

## Test shape

Mirror `contributors.test.ts` exactly. Pure-logic tests:

- `composeKey` returns the expected suffix
- `decodeValue` accepts a canonical row + accepts each nullable field
  as null + accepts JSONB-opaque fields with any shape
- `decodeValue` rejects every kind of malformed input (empty strings,
  wrong types per field, NaN/Infinity, non-object, null)
- `buildXxxProjection` exposes the right `tableTag` and the closures
  pass through

PG write tests live in integration suites (`apps/operator/lib/llm-testing/...`),
not the projection's own test file. Keep the unit tests pure and fast.

## Schema gotcha

If the table doesn't exist yet, add the `ensureXxxTable()` function
in `apps/operator/lib/ensure-schema-dogfood.ts` first:

1. Add a flag to `DogfoodFlags`.
2. Initialize it `false` in the globalThis seed.
3. Write `ensureXxxTable()` with idempotent `CREATE TABLE IF NOT EXISTS`.
4. Register in `ensureAllDogfoodTables()`'s `Promise.all`.

The dogfood schema is intentionally separate from `ensure-schema.ts`
(operator's older tables) — keep new HYPERBEE tables in the dogfood
file.

## Where to wire registration

When boot wiring lands in `instrumentation-node.ts`:

```ts
// per harness:
registerProjection(buildContributorsProjection({ workspaceId, harnessSlug }));
registerProjection(buildHarnessFeaturesProjection({ workspaceId, harnessSlug }));
// ...etc for all 8.
```

The substrate's `applyHyperbeeOpToPg(op)` then dispatches by `op.table`
to the right projection's `writeToPg` / `deleteFromPg`.
